# Avonmoor — Render Frankfurt staging

Deploy from `feature/render-frankfurt-migration` first. Keep PythonAnywhere and DNS unchanged until acceptance tests pass.

## Render web service

- Region: Frankfurt
- Runtime: Python
- Python version: `3.11.11` (`PYTHON_VERSION`)
- Build command: `bash build-render.sh`
- Start command: `gunicorn avonmoor.wsgi:application --bind 0.0.0.0:$PORT`
- Health check: `/` (initially; replace with a dedicated endpoint later)
- Automatic deploys: off during migration

## Required environment variables

- `DJANGO_SECRET_KEY`: new securely generated secret, stored only in Render
- `DATABASE_URL`: PostgreSQL connection string for an Avonmoor-specific database (not Hot Pressed's database)
- `ALLOWED_HOSTS`: `avonmoor-frankfurt.onrender.com,www.avonmoor.co.uk,avonmoor.co.uk`
- `CSRF_TRUSTED_ORIGINS`: `https://avonmoor-frankfurt.onrender.com,https://www.avonmoor.co.uk,https://avonmoor.co.uk`
- `EMAIL_BACKEND`: `django.core.mail.backends.smtp.EmailBackend`
- `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_USE_TLS`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`: verify outbound SMTP compatibility and use Render secret settings
- `GOOGLE_MAPS_API_KEY`: browser-restricted key; allow the staging host during testing
- `PYTHON_VERSION`: `3.11.11`

## First release

1. Establish isolated PostgreSQL storage. Sharing a Render Postgres *instance* requires a separate database and suitable credentials; do not point both Django applications at the same tables.
2. Configure environment variables and deploy staging web service.
3. Run `python manage.py migrate --noinput` from Render Shell after confirming `DATABASE_URL`.
4. Create a fresh administrator with `python manage.py createsuperuser` from Render Shell; do not transmit credentials in chat.
5. Import rainfall reference CSV using `python manage.py import_rainfall_grid /path/to/rainfall.csv` and verify point counts/coverage. The CSV is not generated by migrations.
6. Test homepage, static assets, admin, survey forms, postcode lookup, calculator rainfall estimates, Maps API, and enquiry notification emails.
7. Move custom domain and DNS only after successful acceptance testing; then retire PythonAnywhere.

## Notes

- The current project stores media in a local folder. Render web service filesystems are ephemeral; inspect whether persistent user uploads exist before cutover.
- Avoid running database migrations in the build phase; they require an accessible database and should be a controlled release step.
- The existing Oregon Hot Pressed database is a separate retirement task and must not be confused with Avonmoor storage.
